## 2026-11-13 Our road graph for the lower 48: the build and the hosting (claude/project-thread-39xbx9)
- Big bet #2 (docs/notes/2026-11-13-big-bets.md): our router (fun scored into every edge, works offline) covers OH/KY/IN
  only; elsewhere Fun, Long way and loops fail honestly. This PR is the pipeline for the whole lower 48.
- R2 is not enabled on the account (the API says "Please enable R2 through the Cloudflare Dashboard": needs the owner's
  card, bet #1), and ~4 GB a build would bloat the graph-data branch on every rebuild. So: GitHub releases, free for a
  public repo and outside git history.
- `tools/graph_etl/us_plan.py`: Geofabrik's index -> the lower-48 states and their boxes; one job per 1 degree band x
  15 degree chunk (no job past 6 h: Ohio's densest ten blocks took 105 min), blocks only where a state touches, each job
  fetching the states under its blocks' 0.4 degree margins. `--only` makes a pilot.
- `tools/graph_etl/pack.py`: tiles into 2 degree packs (a release takes 1000 files; the token about 1000 requests an
  hour), packs.json (tile -> pack, offset, length) and the phone's slim index.json.
- `.github/workflows/graph-us.yml`: plan -> osm (each state downloaded once, an artifact) -> band (graph-region.yml's
  per-block build; a failed block keeps the rest and fails the job for a re-run) -> publish (merge, pack, release, then
  the graph-data pointer `us/v1/current.json`; the two newest US releases kept).
- `backend/src/graph.ts`: with a pointer, the index and packs from the release (memoized per isolate an hour) and each
  tile as a Range of its pack (a 200 without Range: cut from the whole pack); bad tag, missing files or packs of another
  build: the branch's tiles as before. No pointer is asked again only hourly.
- Tests: `test_graph_us.py` (plan, packs byte for byte, the workflow's order), `backend/test/graph.test.ts` (release
  tiles by Range, without Range, the fallbacks).
- West Virginia pilot (run 43513750093): 8 band jobs, 51 min, 384 tiles, 157 MB in 12 packs; tiles read back by Range
  decode with their own i/j. Two Geofabrik downloads were refused at 6 at a time: now 4, with --retry-all-errors.
- First full run (43524664679, 2026-11-14): 47 states downloaded (Florida on a re-run: Geofabrik refused the runner),
  then one block on the Lake Superior shore (48N 89W: one way, no road chain) crashed shapely in features.near_counts on an
  empty query; cancelled. Fixed (near_counts and build.py return early with no chains; tests in test_graph_etl.py), and the
  download now tries three rounds five minutes apart.
- Next: the full lower 48 again from main, which goes live through R2 (below); then the app's "covers Ohio, Kentucky and
  Indiana so far" lines.

## 2026-11-13 The lower-48 tiles on GitHub releases, not R2 or the branch (claude/project-thread-39xbx9)

R2 needs the owner's card; the branch would grow ~4 GB per rebuild. Releases are free and kept out of the repo's
history; reads go through the Worker, so moving to R2 later changes graph.ts only. The workflow deletes US releases
older than the two newest (generated data). Undo: delete `us/v1/current.json` on graph-data (the Worker falls back
to the branch within an hour).

## 2026-11-13 The lower 48 goes live in our R2 bucket, the release as fallback (claude/project-thread-39xbx9)
R2 arrived the same day (#680) and the Worker reads R2's index before any release, so a US build published only as a
release would never be served. The publish job now uploads the tiles and the slim index to R2 (upload_r2.sh, the
run's OIDC token) before writing the release pointer; builds are named `us-<week>-...` so their R2 keys and edge-cache
keys never meet the region's (the pilot shared the region's build id); and the region's weekly mirror skips the graph
while a `us-` build is live, so it never shrinks the map back to three states. Undo: re-run "Map data to R2" after
deleting the `us-` guard in upload_r2.sh (the region index goes back on top).
